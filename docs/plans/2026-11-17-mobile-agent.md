# 手机端 Agent：方案、M0 与 M1 结果

2026-11-17 · 状态：M0、M1 在模拟器上完成并验收；尚未在真机上测试

## 定位

手机本身就是 Agent：模型在手机上思考、在手机上操作 App，沿用 Super 的规矩——先授权再执行、有预算、风险步骤要人审批、做完要独立验收。

```
手机 App（Kotlin 薄壳：无障碍服务 = 设备桥、悬浮状态条与审批卡片、Keystore、任务界面）
        │ gomobile 生成的 Java 接口，进程内调用，JSON 进出
        ▼
Go 核心（mobile/niumacore 对外接口 + mobile/phone 门卫与任务运行器）
        │ 复用 internal/super/execution（模型调用、预算、授权检查、手机工具）
        │ 回调接口 DeviceBridge：Go 定义、Kotlin 实现
        ▼
   其他 App
```

实现完全基于 Android 与 Go 的官方公开能力和本仓库已有代码。

## M0 发现的问题与处理

1. **App 进程没有 `$HOME`**：`super.StateDirectory()` 取不到默认的 `~/.super-niuma`，执行器按"授权失效"拒绝（正确的失败关闭）。处理：`niumacore.Init(stateDir)` 把 Super 状态目录显式设到 App 私有目录 `files/super-state`，模型工作区是它的兄弟目录。
2. **SELinux 不允许 App 读取 `/`，`/data`、`/data/data` 为 0771**：执行器校验工作根时从 `/` 起用 `O_RDONLY` 逐级打开，在手机上必然失败（`avc: denied { read } ... tclass=dir`）。处理：Linux 上改用 `O_PATH` 逐级打开（只需穿过权限，仍带 `O_NOFOLLOW|O_DIRECTORY`，末端 inode 比对不变），macOS 保持 `O_RDONLY`。见 `internal/super/execution/files_walk_{linux,darwin}.go`。
   - 新增 Linux 测试：不可列目录的父路径能通过、符号链接父路径仍被拒绝。
   - 把 execution 的测试编成 Android 可执行文件、在模拟器内核上以 shell 身份运行：44 项通过；1 项失败是测试夹具本身无法在 `/data/local/tmp` 建硬链接和 FIFO（SELinux 拒绝），不是被测代码问题。
3. **强行停止会关掉无障碍服务**：`am force-stop` 后系统把服务从已启用列表移除（设置值变为 `null`），必须由用户重新开启。M1 要能检测并引导。
4. **gomobile 会升级 golang.org/x 依赖**：把手机核心放进嵌套模块 `mobile/go.mod`，根模块依赖不变。根目录 `go test ./...` 不覆盖 `mobile/`。
5. **gomobile 构建会对整个依赖图执行 `go mod tidy`**：默认 `goproxy.io` 偶发连接重置，构建时可临时指定 `GOPROXY=https://goproxy.cn,https://proxy.golang.org,direct`。

## M1：Agent 真正操作手机

M1 的运行中审批放在手机这一侧（`mobile/phone`），没有改 Super 控制面：执行到风险步骤时，那次工具调用停住等人。任务和每一步记在手机上的 SQLite 里。

| 内容 | 实现 |
| --- | --- |
| 验收器在手机上打开工作区 | `internal/super/verification` 在 Linux 上改用 `O_PATH` 逐级打开并比对 inode；App 内自检 `VerifyProbe` 通过，无 SELinux 拒绝 |
| 执行器手机工具 | `internal/super/execution` 新增 `super_screen / super_tap / super_type / super_swipe / super_key / super_launch`；只有请求带 `Device` 时才出现，每次动作前做授权检查，回合上限 40 |
| 门卫 | 只把任务允许的应用和桌面的界面给模型看，其他应用（含通知栏）只给名字、隐藏内容；只在这些应用里动手；动作前用新读的界面核对目标，变了就拒绝 |
| 风险与审批 | 发送、付款、删除、安装、拨号、发布、转账、提交（按文字或控件 id 判断），以及在聊天应用里按回车：先等人。拒绝、60 秒无人处理或按停止都不执行；批准后目标必须还在原处才执行 |
| 凭据 | 不往密码和验证码输入框里打字，交还给人；模型密钥用 Keystore 加密保存，不进任务记录和日志 |
| 停止与恢复 | 悬浮状态条上的“停止”立即结束任务；进程被杀后，重启时把任务标为“中断”，不自动重做 |
| 验收 | 任务结束后重新读屏，核对“完成后应出现的文字”；没设验收文字而又有步骤被拒，标为“需要你检查” |
| CI | race 作业覆盖整个 `mobile` 模块；新增 `mobile-android` 作业打包 Go 核心、跑 Kotlin 单测、构建 debug 和 release |

### M1 验收

在 Android 14 模拟器（arm64）上用真实模型（`agnes-2.5-flash`，经开发机中转，密钥不进手机）从全新安装跑 `mobile/scripts/m1-acceptance.sh`：**18 项全部通过**，34 次模型请求。审批和停止都是真实点击悬浮按钮。记录与截图在 `mobile/android/build/validation/20261117/m1/`。

| 场景 | 结果 |
| --- | --- |
| 屏幕助手关闭 | 拒绝开始任务；打开后核心立即接上设备桥 |
| 模型设置 | 经 Keystore 加密保存并读回一致 |
| 设一个早上 7:00 的闹钟 | Agent 约 13 步完成；任务结束后重新读屏，验收通过；闹钟列表里确有 7:00 |
| 删除 7:00 闹钟，人拒绝 | 点“删除”时停下等审批；拒绝后没有执行，任务为“需要你检查”，闹钟仍在 |
| 删除 7:00 闹钟，人允许 | 批准后才删除，闹钟消失，8:30 仍在 |
| 运行中按悬浮条“停止” | 任务为“已停止”，之后 8 秒内没有任何动作 |
| 任务中杀掉 App 进程 | 重启后任务为“中断”，已执行的步骤保留，没有自动重做 |
| 让它去看系统设置（只允许时钟） | 打开设置被拒绝（`scope_denied`），范围外应用里没有执行任何点击、输入或滑动；Agent 回答“无法检查 Wi‑Fi” |
| release 构建 | 测试命令入口关闭 |
| 稳定性 | 整轮没有崩溃 |

此前几轮的失败，原因和处理都已记录：脚本问题（模型设置等待太短、时间文字里的窄不换行空格、`wait` 等到了中转进程、审批卡片截早了），以及模型服务限流（429）和一次回复被截断。脚本已修正；脚本遇到 429 或回复截断时，会冷却后重试一次并在结果里注明。另外，Agent 的文字总结不可靠：三次说列表里有一个和状态栏时间相同的闹钟，截图里都没有。

### M1 中发现并修掉的问题

1. **对被盖住的应用执行点击会"假成功"**：批准后、点击前，测试脚本把主界面拉到前台盖住了时钟；`ACTION_CLICK` 返回成功但闹钟没删。设备桥现在只对前台应用的元素动手，否则返回失败。
2. **越界读屏**：Agent 被拒绝打开系统设置后，在桌面下滑拉出了通知栏，执行后返回的屏幕里带着通知栏内容（读到了 Wi‑Fi 状态）。现在范围外的应用只给名字、隐藏内容。
3. **只有图标的风险按钮绕过审批**：没有文字、只有 `send_button` 这类 id 的按钮原来判断不出风险，现在也按 id 判断。
4. **超时后再点“允许”被报成成功**：现在超时即关闭这次审批，迟到的“允许”会被拒绝。
5. **审批卡片可能接住手势**：批准后卡片先移除再放行，手势执行时卡片也让触摸穿透。
6. **模型单次回复超出 1024 token 时任务失败**：一些模型会先写一段说明再调工具，上限提到 2048。
7. **Agent 的总结会说错**：一次删除任务后，Agent 说列表里还有一个 2:58 PM 的闹钟，截图里并没有（2:58 是状态栏时间）。所以状态以验收为准，没设验收文字的任务显示“完成（未验收）”。

## 模型请求重试（M1 之后）

验收中多次因为模型服务限流（429）整轮失败。现在 Super 执行器对**模型请求**的瞬时故障做有界重试，桌面 Super 和手机任务默认都开启（`execution.DefaultRetryPolicy`，详见 `internal/super/execution/README.md`）：

| 类别 | 情形 | 做法 |
| --- | --- | --- |
| 确定没被处理 | 429、408、503、529（响应里不是额度耗尽），连接根本没建立 | 在同一份预算预留里原样重发；遵守 `Retry-After` |
| 可能已被处理 | 500、502、504，发出后的网络错误或超时，响应读到一半断开 | 旧预留按已花掉保留（不退），新预留一份再发 |
| 永久错误 | 401/403、其他 4xx、重定向、额度耗尽、地址解析失败，以及完整响应里的任何问题（JSON 错误、缺用量、被截断、空回复、被拒答） | 不重试 |

上限：每个请求最多重发 3 次，退避 2 s 起翻倍，单次等待不超过 60 s（`Retry-After` 更长就直接失败），每次执行累计等待不超过 3 分钟，也不越过执行本身的时限。等待可以随时取消，每次重发前重新检查授权。手机上，悬浮条会显示“模型服务限流，6 秒后重试（1/3）”。

**不重试的边界**：点击、发送、删除等手机动作，以及 Super 对外的投递，结果不确定时照旧报告、不重做。

## 通知与提醒（M1 之后）

人不看屏幕时也要知道任务在等他、结束了，或者屏幕助手被关了。三类系统通知，各占一个渠道，人可以分别关掉：

| 通知 | 何时出现 | 做法 |
| --- | --- | --- |
| 需要你确认 | 有一步在等审批 | 写明要做什么、在哪个应用、理由和剩余秒数，带“拒绝”“允许一次”两个按钮；锁屏上只显示“超级牛马有一步需要你确认”，Android 12 起“允许一次”要先解锁；审批被回答、换成下一个或超时后撤回 |
| 任务结果 | 任务结束 | 完成并已验收 / 完成（未设置验收文字）/ 需要你检查 / 失败 / 中断；人自己按的停止不通知；开始新任务时撤回上一个 |
| 屏幕助手已关闭 | 应用运行中服务被解绑且系统设置里已关；或应用启动时发现之前开着、现在关了（强行停止后） | 点一下打开系统无障碍设置；服务重新连上后撤回 |

配套改动：

1. **失去屏幕助手时任务记为“中断”**（`screen_reader_off`），不再记为“人停止”，所以会收到“任务中断”的通知。
2. **在通知栏或主界面批准后，等应用回到前台再动手**：通知栏或主界面会短暂盖住应用，门卫最多再读 8 次（约 3 秒），应用回来且目标还在才执行，否则照旧按“界面已变”拒绝。点通知里的按钮后会收起通知栏，在主界面批准后主界面会退到后台。
3. **任务不能把系统界面（通知栏）或超级牛马自己列为可用应用**：通知里的审批按钮和主界面都能回答审批，Agent 不能碰它们。
4. 每个审批的按钮各有自己的 PendingIntent（审批编号在 data URI 里），按钮只能回答它显示时的那个审批；核心也只接受仍在等待的审批编号。
5. 没有通知权限（Android 13 起要用户允许）或渠道被关时，审批照旧走悬浮卡片和主界面，主界面会写明“通知未开启”。

限制：强行停止会同时杀掉进程并关掉服务，系统不给应用任何回调，所以“已关闭”的提醒要等下次打开应用时才出现。

验收（模拟器 Android 14，真实模型，`mobile/android/build/validation/20261117/m1-notify`）：35 项全部通过。新增的检查有：设闹钟后收到“任务完成，已验收”；在通知里拒绝（通知为锁屏隐私、两个按钮）和在通知里允许（收起通知栏后应用回到前台，删除执行）；任务中途关掉屏幕助手 → 任务中断（`screen_reader_off`）、立即提醒、收到“任务中断”，点提醒进入无障碍设置，重新开启后提醒撤回；强行停止后下次打开应用时提醒；撤销通知权限后提醒被跳过且不崩溃。第一轮有一个场景因模型服务连续 4 次 429 先失败了，脚本已让这个场景和其他场景一样先冷却、遇到服务问题重试一次。
